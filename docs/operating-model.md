# Operating Model

## Roles

### Human founder
Owns mission, customer promise, risk appetite, reserved decisions, budgets, and final accountability.

### AI CEO / coordinator
Maintains the operating plan, breaks outcomes into work, selects authorized workers, manages dependencies, identifies blockers, and produces concise evidence-backed reports. It cannot grant itself new authority.

### Specialist workers
Execute bounded tasks. Each has a role contract, defined inputs/outputs, tool permissions, and escalation rules.

### Review function
Checks deliverables against acceptance criteria, verifies claims and tests, and identifies risk. A reviewer agent is a quality aid, not a substitute for independent human judgment on high-impact decisions.

## Work lifecycle

1. Intake: capture desired outcome, context, owner, deadline, and constraints.
2. Triage: classify value, uncertainty, risk, and effort.
3. Authorize: confirm scope, budget, tools, and approval requirements.
4. Plan: define tasks, dependencies, and acceptance criteria.
5. Execute: workers produce artifacts and evidence.
6. Review: check correctness, quality, security, and policy.
7. Approve: a human approves reserved actions.
8. Deliver: publish, deploy, send, or hand off only within authorization.
9. Learn: measure outcomes and record incidents/lessons.

## Start small

Begin with a coordinator and one or two specialist roles. Add roles only when there is recurring work with a clear handoff. An elaborate org chart creates overhead if no repeatable workload exists.
